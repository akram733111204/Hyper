# البنية الهندسية — نظام الركن للصلاحية

## مصادر الحقيقة

- **XLSX داخل مجلد التطبيق الخاص**: المصدر الدائم للمنتجات والتشغيلات والمهام والعمليات والإعدادات.
- **CatalogProducts/BarcodeAliases**: مصدر مرجعي منفصل داخل دفتر التطبيق لتعرف هوية المنتج؛ لا يملك صلاحية تعديل أو حذف التشغيلات أو التواريخ أو الملاحظات.
- **المعلومات الخارجية**: معلومات مساعدة لا تعد مصدرًا موثوقًا تلقائيًا إلا بعد التحقق من العبوة.
- **تواريخ التشغيلات**: بيانات يراجعها الموظف قبل حفظها، ولا تُستنتج من الباركود العادي.
- لكل منتج `id` ولكل تشغيلة `id`، لتجنب ربط سجلات الصلاحية باسم المنتج أو باركود متغير.

## تدفق المسح

1. `CameraX` يقرأ إطارات الفيديو؛ `ML Kit` يكتشف الباركود دون صورة ثابتة.
2. يحدد المستخدم طريقة البحث: تلقائي (محفوظ ثم كتالوج ثم الإنترنت)، محلي فقط، إنترنت فقط، أو يدوي.
3. إذا لم تُعثر معلومات المنتج، يبقى الباركود المقروء وتفتح الحقول اليدوية تلقائيًا، دون أي إدخال إجباري.
4. الاستعلام عن خادم HTTPS المعتمد عند تهيئته. البيانات المجتمعية اختيارية وغير رسمية.
5. بعد الضغط على «التالي»، يُنشأ مسار إدخال صوتي: Android SpeechRecognizer أو OpenAI Live عبر خادم خاص مرخص، حسب إعدادات المستخدم.
6. يقرأ محرك فهم منفصل النص النهائي ويقترح أوامر منظمة على الحقول، وينبه للأرقام والتواريخ الملتبسة؛ المحرك المحلي محدود، والفهم الدلالي السحابي اختياري ومشروط بموافقة المستخدم.
7. يعرض التطبيق الأوامر للمراجعة قبل تطبيقها على النموذج، ثم مراجعة ثانية لتواريخ العبوة قبل الحفظ.
8. `AtomicFile` يضمن الاستبدال الآمن للملف المحلي وقت الحفظ.

## أوراق Excel

| الورقة | مفتاح السجل | الاستخدام |
|---|---|---|
| Products | id | المنتجات والأسماء والباركود والرف والتحويل |
| Batches | id -> productId | تواريخ الإنتاج والانتهاء والكمية والموقع وحالة التحقق |
| Tasks | id -> batchId | مهام الفحص والمراجعة |
| AuditLog | id | أحداث التعديلات |
| Settings | key | إعدادات مصادر الإنترنت |
| Metadata | key | رقم إصدار المخطط (`schema=2`) وتاريخ الكتابة |
| CatalogProducts | id / barcode | تعريف المنتجات المستورد، دون ملاحظات أو تواريخ تشغيلات |
| BarcodeAliases | alternateBarcode | ربط باركود بديل موثق بباركود رئيسي |

> نسخة `schema=1` تقرأ وتُرقّى عند الحفظ التالي دون تغيير المنتجات والتشغيلات؛ أضيف اختبار ملف v1 حقيقي.
> مسار استيراد الكتالوج يفحص المحتوى ويعرض معاينة ويُجري دمجًا آمنًا؛ ولا يستخدم «استعادة Excel كاملة».

## حدود النسخة الحالية

- تصميمها **لجهاز واحد**؛ لا توجد مزامنة تلقائية بين هواتف متعددة.
- حفظ ملف XLSX كامل عند كل عملية أسهل للموثوقية لكنه ليس الحل الأسرع إذا تجاوزت البيانات عشرات الآلاف من السجلات؛ يلزم اختبار الأداء على أجهزة مستهدفة وتطوير تخزين تدريجي أو Cache عند الحاجة.
- لا يوجد توقيع APK رسمي أو إصدار Play Store ضمن المشروع. بناء GitHub Actions ينتج **Debug APK** للاختبار.
- لا يوجد اتصال مباشر مضمون بالسجل السعودي قبل الحصول على تصريح وواجهة API موثقة واختبارها.
- أُزيل مسار قراءة التواريخ بالكاميرا من الإصدار الجديد؛ دقة الصوت العربي المحلي تعتمد على دعم الهاتف، كما يحتاج المحرك السحابي إلى خادم ومفتاح API واختبار ميداني.
- التنبيهات حاليًا **داخل التطبيق**، وليست إشعارات نظام Android المجدولة أثناء إغلاقه.
- Excel يمكن فتحه في برنامج خارجي؛ لا تعدل الملف في نسختين مختلفتين ثم تدمجهما تلقائيًا.
- ما يعرضه التطبيق من كمية مخزون هو **الكمية المدخلة يدويًا للتشغيلات** وليس رصيدًا آنيًا من نظام المبيعات.

## ضمانات البيانات

- لا حقل يدخله المستخدم إجباريًا عند إنشاء منتج.
- لا يُخترع يوم لتاريخ مطبوع بالشهر والسنة فقط.
- لا تنشئ عملية مسح إضافية رصيدًا تلقائيًا دون تدقيق.
- لا تعتمد تفريغات الصوت أو أوامر AI دون معاينة وتأكيد بشري؛ لا تتغير البيانات الدائمة بمجرد النطق.
- تنبيه التكرار قائم على المنتج والتاريخ ورقم التشغيلة والموقع، مع إمكانية تجاوز واعية.
- استخدام أسماء عربية في البحث يدعم الألف والهمزات والياء والألف المقصورة والتاء المربوطة والزوائد وبعض الأخطاء القريبة.

## الاختبارات المطلوبة قبل التشغيل الفعلي

1. هاتف Android حقيقي وإذن الكاميرا وتعدد أنواع الباركود.
2. عينة صوتية واقعية تشمل لهجات الموظفين وضوضاء المتجر والتواريخ والأعداد والقياسات، مع مقارنة المخرجات بالحقائق المؤكدة.
3. استعادة نسخة Excel والبحث عن آلاف المنتجات بالباركود والاسم.
4. فشل عملية الحفظ وانقطاع الهاتف والتأكد من الاستعادة.
5. قراءات زمنية مختلفة للتواريخ (يوم/شهر و/أو شهر/سنة) وتأكيد الحدود.
6. تحقق من مصدر بيانات SFDA عبر اختبار تعاقدي بعد الحصول على تصريح وخدمة فعلية.

## قرار تأجيل إثراء البيانات جماعيًا
