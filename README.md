# الركن | نظام إدارة صلاحية منتجات الهايبر ماركت

![شعار الشركة](app/src/main/res/drawable/rukn_logo.jpg)

**النسخة التطويرية 0.3.0 — مشروع Android أصلي (Kotlin + Jetpack Compose + CameraX + ML Kit Barcode + Voice AI)**. مخصص لإدارة المنتجات والتشغيلات وتواريخ الإنتاج والانتهاء، والبحث العربي الذكي عن المنتجات ومواقعها. يدعم حفظ البيانات الأساسي في Excel XLSX، وتصدير التقارير، وإدارة الفحص والتنبيهات.

> **حالة التسليم:** نسخة تأسيسية وظيفية مع شيفرة المشروع واختبارات لمنطق الأعمال وXLSX. لم يتم بناء APK أو اختباره على هاتف في بيئة إعداد المشروع، لعدم توفر Android SDK / Gradle واتصال تنزيل الاعتماديات. تشغيل GitHub Actions هو اختبار البناء الأول؛ لا تعتمد عليه في قرارات السلامة الغذائية قبل نجاح البناء والاختبارات الميدانية.

## بناء APK من GitHub دون تثبيت أدوات على جهازك

1. أنشئ مستودع GitHub فارغًا **خاصًا (Private)** للحفاظ على المشروع والهوية البصرية.
2. فك ضغط ملف المشروع المرفق، ثم ارفع **محتويات** مجلد `rukn-expiry` إلى جذر المستودع، بحيث يكون المسار `.github/workflows/android.yml` موجودًا في جذر GitHub. لا ترفع ملف ZIP مغلقًا فقط.
3. يمكنك استخدام Git على الكمبيوتر:

   ```bash
   cd rukn-expiry
   git init
   git add .
   git commit -m "Initial Rukn Expiry Android project"
   git branch -M main
   git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
   git push -u origin main
   ```

4. من المستودع افتح **Actions → Android CI — بناء وتجربة تطبيق الركن → Run workflow**، أو ارفع الملفات إلى فرع `main` وسيبدأ التشغيل تلقائيًا.
5. بعد نجاح جميع خطوات البناء، افتح آخر Run وابحث عن **Artifacts → Rukn-Expiry-debug-APK**، ثم نزّل الملف وفك الضغط وثبّت `app-debug.apk` على هاتف Android للاختبار.
6. إذا فشل أي اختبار أو بناء، راجع رسالة الخطأ في Action؛ **لا تتعامل مع وجود المشروع في GitHub على أنه إثبات نجاح البناء**.

> هذا Debug APK للاختبار الداخلي فقط. نشر إصدار إنتاجي يتطلب مفاتيح توقيع خاصة، وأتمتة إصدار مستقرة، وتقييمًا أمنيًا واختبارات حقيقية للكاميرا والدقة والأداء.

## المساعد الصوتي في النسخة 0.3.0

- بعد مسح الباركود أو تعبئة بيانات المنتج يدويًا، اضغط **«التالي: إدخال بيانات التشغيلة بالصوت»**؛ إذا توفر الإذن يبدأ الاستماع.
- قل جملة طبيعية تتضمن التواريخ والكمية والمكان والملاحظات؛ يقدم التطبيق ملخصًا بالحقول المقترحة للتحقق قبل تطبيقها.
- يمكن قول «غير شهر الانتهاء إلى نوفمبر» أو «امسح الملاحظات» دون إعادة تسجيل باقي المعلومات.
- توجد قائمة محركات: تلقائي، محرك Android محلي على جهاز مدعوم، محرك Android العام، وOpenAI Live بخادم خاص. **الذكاء الدلالي السحابي اختياري ولا يعمل دون إعداد صريح**، أما تفسير الأوامر المحلي فيغطي أمثلة محددة ولا يمثل نموذج لغة عربيًا عامًا.
- لم تُختبر الكاميرا/الميكروفون على هاتف فعلي، ولا يتضمن المشروع بيانات اعتماد خدمة سحابية. راجع [دليل Voice AI التفصيلي](docs/VOICE_AI_AR.md).

## إعداد الربط الرسمي مع بيانات المنتجات

**لا يتضمن المشروع مفتاحًا رسميًا أو بيانات اتصال معتمدة نيابة عن الشركة.** يمكن للمستخدم إضافة منتج يدويًا دائمًا.

1. احصل على حق وصول مصرح إلى خدمات هيئة الغذاء والدواء أو GS1 السعودية، وراجع شروط الاستخدام وحدود الاستعلام.
2. استضف `server/server.mjs` خلف HTTPS ومصادقة/محددات استعلام مناسبة. جهّز متغيرات البيئة `SFDA_API_URL` و`SFDA_API_KEY` للخادم وحده، وليس في GitHub أو APK. هذه نسخة موصل **تحتاج تأكيد عقد API الفعلي ورموز الحقول** قبل التشغيل على بيانات رسمية.
3. في إعدادات التطبيق أضف عنوان الخادم HTTPS. سيطلب التطبيق `GET /v1/products/{barcode}` ويحفظ اسم المنتج والعلامة والحجم والمصدر عند الاستجابة الصحيحة.
4. خيار Open Food Facts غير رسمي، **معطّل افتراضيًا**، ومتاح فقط كبديل مجتمعي.

المصادر المرجعية: [قائمة الغذاء والدواء](https://www.sfda.gov.sa/ar/products)، [كتالوج GS1 الوطني](https://www.gs1.org.sa/ar/articles/national-product-catalog).

## تخزين Excel

- ملف بيانات داخلي `rukn_expiry.xlsx` في مساحة التطبيق الخاصة؛ المنتج لا يحتاج إلى فتح ملف Excel يدويًا عند كل عملية.
- `Products`: معرف، باركود، الأسماء، العلامة، الحجم، عدد القطع بالكرتون، القسم، الممر، الرف، الملاحظات.
- `Batches`: معرف، المنتج، LOT، الإنتاج والانتهاء، دقة التاريخ، نوعه (انتهاء/أفضل قبل)، الكمية، الوحدة، موقع التشغيلة، الحالة، التحقق والملاحظات.
- `Tasks`: مهام الفحص والمتابعة.
- `AuditLog`: إجراءات وتعديلات وقيم قبل/بعد عند توفرها.
- `Settings`: فترات المراقبة وعنوان موصل البيانات وخياراته.
- `Metadata`: إصدار المخطط وتاريخ الحفظ.
- `CatalogProducts`: كتالوج الباركود المرجعي، مستقل عن منتجات التشغيلات.
- `BarcodeAliases`: الباركودات البديلة الموثقة لنفس وحدة البيع.

**صيغة بيانات Excel الداخلية الجديدة:** `schema=2`. ويدعم القارئ **استعادة ملفات الإصدار السابق `schema=1`** دون محو المنتج أو التشغيلات أو الملاحظات. يجب أخذ نسخة احتياطية قبل كل ترقية.

### كيف تستخدم كتالوج Excel؟

1. من **الإعدادات ← إدارة كتالوج المنتجات والباركود** اضغط **إنشاء قالب Excel فارغ**.
2. أدخل الباركود كنص والبيانات المتاحة داخل ورقة `ProductCatalog`. ورقة `BarcodeAliases` اختيارية.
3. اضغط **استيراد كتالوج المنتجات من Excel**؛ شاهد المعاينة قبل اعتماد الدمج.
4. استخدم الوضع التلقائي أو المحلي عند مسح باركود جديد، وإن لم توجد بيانات انتقل تلقائيًا للإدخال اليدوي.
5. راجع أيضًا [دليل الكتالوج الكامل](docs/CATALOG_IMPORT_AR.md).

**ملحوظة:** لم ننفذ آلية إثراء بيانات المنتجات الناقصة **جماعيًا عبر الإنترنت عند الاتصال** حسب طلب حذف الاقتراح السادس. الجلب الخارجي عند مسح منتج واحد ما زال ممكنًا عند توفر موصل مصرح به.

استخدم **التصدير إلى Excel** لنسخ الملف خارج الهاتف دوريًا. الاستعادة **استبدال كامل وليست دمجًا**، وتحتاج إلى تأكيد المستخدم.

## التحقق والاختبار

أُجري اختبار محلي فعلي باستخدام مترجم Kotlin المتاح:

```bash
bash scripts/test-core-local.sh
```

النتائج المحلية: نجاح اختبار البحث العربي، وتحليل التاريخ بأرقام عربية، وحساب الكراتين والحبات، وقراءة XLSX بعد كتابته مع النص العربي والأصفار الابتدائية للباركود. يوجد أيضًا اختبارات JUnit بمجلد `core/src/test` تُشغّل عبر `:core:test` في CI.

### أمور يجب إكمالها واختبارها قبل التشغيل المؤسسي

- **لم يصدر APK مُتحقق منه بعد**؛ بناء Android في GitHub Actions يلزم للتحقق من Gradle وCompose وتبعيات الهاتف.
- أُزيل OCR الخاص بتواريخ العبوات؛ مساعد الصوت الجديد يحتاج إلى اختبار الميكروفون واللغة العربية على هواتف المستخدمين، مع تمييز ما لا يستطيع الموظف نفسه إثباته على العبوة.
- لا يمكن ضمان صحة تاريخ مطموس حتى عند نطقه؛ يجب الرجوع إلى معلومات التشغيلة أو العزل والفحص بحسب إجراء الشركة.
- إشعارات الصلاحية **حاليًا داخل التطبيق**؛ إشعارات خلفية مجدولة تحتاج تنفيذًا إضافيًا وتأكيد صلاحيات Android.
- التزامن متعدد الأجهزة، صلاحيات الموظفين، وخادم مؤسسي مركزي **غير مفعلة** في هذا الإصدار.
- التقارير المالية وربحية الأصناف ليست متاحة دون بيانات أسعار/تكلفة.
- تحويل الكراتين إلى حبات لا يجري إلا بمعامل صحيح ووحدة مقروءة؛ لا تُخترع معلومات مخزون.
- أداء الكتابة إلى XLSX يحتاج إلى اختبار مع حجم السجلات الفعلي، وبخاصة الحفظ المتكرر والعشرات الآلاف من التشغيلات.
- استيراد كتالوج جديد مستقل عن «استعادة نسخة Excel كاملة»؛ لا ترفع كتالوج الباركود من زر الاستعادة القديم.
- اختبار محلي جديد للكتالوج: القالب السابق، منع التكرار، التعارضات، الباركود البديل، البحث، توافق النسخ الاحتياطية القديمة `schema=1`.
- لم يُجر اختبار ميداني للصوت أو للكاميرا أو تكامل السحابة؛ لا تعتمد على النتائج وحدها لقرار سحب أو بيع منتج.
